# 다음 작업 하네스 — 좀비 TPS (GPT-6)

이 문서는 2026-09-23 사용자 요청의 **다음 작업 범위**를 정리한다. 구현 시 이 저장소의 `AGENTS.md`를 함께 따른다. 이 문서의 게임 요구와 오래된 기획 문서가 충돌하면 최신 사용자 요청을 우선하고, 정해지지 않은 수치는 확정 사양처럼 만들지 않는다. 문서 자체는 구현 승인이나 완료 판정이 아니다.

## 작업 시작 순서

1. `git status --short`로 기존 변경을 확인하고, 관련 스크립트·씬·프리팹의 실제 연결을 읽는다. 기존 변경을 덮어쓰거나 일괄 정리하지 않는다.
2. `Assets/Scripts/SurvivalHud.cs`, `UIManager.cs`, `PlayerHealth.cs`, `PlayerShooter.cs`, `Gun.cs`, `GunData.cs`, `ZombieSpawner.cs`, `ItemSpawner.cs`, `Zombie.cs`를 기준으로 현재 데이터 흐름을 그린다. 코드 존재만으로 게임 화면 동작을 완료로 표시하지 않는다.
3. 한 번에 한 플레이 가능한 기능 묶음을 구현한다. 데이터 정의 → 런타임 상태/규칙 → 씬·Inspector 연결 → HUD/알림 → 검증 순서로 마무리한다.
4. 작업 끝에는 변경 파일, 실제 확인한 동작, 미확인 항목, 남은 결정 사항을 기록한다. 체크리스트는 증거가 있는 항목만 체크한다.

## 확인된 현재 상태

- Unity `6000.3.10f1`, URP `17.3.0` 프로젝트다.
- `SurvivalHud`에 나침반형 표시, 체력 수치, 탄약·주무기 표시와 보조무기·수류탄 자리 표시 코드가 있다. 사용자가 제공한 1920×1080 Game 뷰 스크린샷에서 현재 HUD가 보이며, 다른 해상도 검증은 별도다.
- `Gun`/`GunData` 중심의 단일 총기 흐름, `PlayerHealth`, `ZombieSpawner`, `ItemSpawner`, `Zombie`가 있다.
- 주·보조 무기 슬롯과 교체/재획득, 스나이퍼 관통, 샷건, 권총, 근접무기, 수류탄, 속도 포션, 헤드샷 판정, 바리케이드 전용 시스템은 현재 코드에서 확인되지 않았다. 구현 전에 씬·프리팹·외부 패키지까지 다시 확인한다.

## 이번 설계의 요구

| 영역 | 목표 동작 |

## 구현 경계

- 무기 데이터(종류·피해·탄약·사거리·관통/산탄 설정)와 플레이 중 무기 상태(장탄수·예비탄·장착 슬롯)를 분리한다. UI는 이 상태를 읽고, 발사나 아이템 소비 규칙을 소유하지 않는다.
- 적 피격은 `RaycastHit`의 실제 타격 부위를 식별한 뒤 피해 계산으로 전달한다. 관통 대상은 같은 발사에서 중복 피해를 받지 않게 하고, 장애물·아군·최대 대상 수 규칙을 명시한다.
- 무기 아이템 생성과 보급품 생성은 기존 `ItemSpawner`의 책임과 충돌하지 않도록 통합 또는 명시적으로 분리한다. 유효한 NavMesh/지면 위치를 찾지 못하면 생성을 건너뛰고 오류를 관찰 가능하게 한다.
- 나침반의 적 표시는 등록된 살아 있는 적만 대상으로 하고, 거리 제한·위치 계산·카메라 회전을 분리한다. 기존 스포너의 좌표/AABB 이슈가 해결됐다고 가정하지 않는다.
- 바리케이드 단계·내구도·설치/보강 시간은 설정 데이터로 두고, 작업 중단·사망·웨이브 전환 시 상태를 정의한다. 웨이브 진행은 기존 `ZombieSpawner`의 실제 완료 조건과 연결한다.
- 기존 `AGENTS.md`의 책임 경계, 상태 전환, Inspector 참조, 생명주기·검증 규칙을 유지한다. 이 문서만을 근거로 전체 시스템을 재작성하지 않는다.

## 권장 작업 단위

현재 진행 중인 무기 슬롯 단계: `PlayerShooter`의 공개 `Primary Gun`·`Secondary Gun` 필드에 초기 `Gun` 컴포넌트가 붙은 **프리팹**을 Inspector에서 지정한다. 주무기는 필수이고 보조 슬롯이 비어 있으면 2번/휠 전환을 무시한다. 기존 씬에 배치된 총은 중복 표시되지 않도록 비활성화된다. 각 프리팹에는 `Gun`, `GunData`, `Fire Transform`, `Left Handle`, `Right Handle`이 필요하다. 나중에 무기 아이템을 획득하면 `PlayerShooter.EquipWeapon(1 또는 2, 획득한 Gun 프리팹)`으로 해당 슬롯을 교체한다. 1/2와 마우스 휠 전환, 탄약 유지, HUD 변경은 사용자가 Unity 에디터에서 확인할 예정이므로 확인 전 완료로 체크하지 않는다.

1. **기반·HUD 확인:** 현재 HUD의 Game 뷰 표시와 수치 연결 검증, 무기 슬롯·수류탄 표시의 실제 상태 모델 정의.
2. **무기 획득·교체:** 주/보조 슬롯, 픽업과 버림, 기존 무기 재획득 규칙, 무작위 무기 생성 및 알림.
3. **전투:** AR 기준 동작 보존 후 스나이퍼 관통, 샷건, 권총, 근접, 헤드샷, 수류탄을 각각 독립 검증.
4. **보급·웨이브:** 네 가지 보급품, 생성 조건, 웨이브 알림을 실제 플레이 흐름에 연결.
5. **은신처:** 바리케이드 설치·보강·피해·작업 시간과 웨이브 연동.

각 단위는 컴파일, 씬/프리팹 참조, 플레이 모드에서 정상·경계 사례가 확인된 뒤 완료로 표시한다. Unity 실행 검증이 불가능하면 그 사실과 수동 확인 절차를 남긴다.

## 구현 전에 결정하거나 설정값으로 남길 항목

스나이퍼 관통 확률과 관통 조건, 샷건 탄환 수·퍼짐·유효 거리, 권총의 무한 탄약과 재장전 관계, 근접무기 3종의 실제 채택 여부, 수류탄 최대 소지량·반경·피해, 속도 포션 배율·지속 시간, 헤드샷 피해 배율, 아이템 생성 간격·확률·동시 상한, 바리케이드 설치 위치·비용·단계별 수치, 알림의 표시 시간과 우선순위는 아직 확정되지 않았다. 작업에 꼭 필요한 경우 조정 가능한 최소 가정을 명시하고 사용자 결정이 게임 규칙을 바꾸는 항목은 질문으로 분리한다.
